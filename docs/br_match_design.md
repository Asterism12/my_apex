# Apex 20队大逃杀模拟系统设计

## 一、系统概述
基于原有的 3v3 战斗模拟引擎，大逃杀（Battle Royale）模式扩展为 20 支队伍（共 60 名玩家）在同一张大型地图上进行的生存竞技。游戏不仅考察队伍本身的战斗力（枪法、经验），还引入了宏观的**地图探索**、**资源搜集（Loot）**、**缩圈机制**以及**多队混战（劝架/Third-party）**。模拟持续进行，直到地图上仅剩一支队伍存活。

## 二、核心模块扩展

1. **大地图与随机出生模块**
   - 将原战场的“单一沙盒”扩展为包含多个物资区（POI, Point of Interest）的连通图或网格地图。
   - 初始化时，20 支队伍拥有各自的初始跳伞落点。

2. **宏观Tick与微观Tick双层引擎**
   - **宏观地图Tick（例如1 tick = 1秒）**：处理队伍移动、进圈、搜集物资、相遇判定。
   - **微观战斗Tick（例如1 tick = 0.1秒）**：当两支或多支队伍在地图同一区域相遇且距离小于交火阈值时，自动实例化一个局部“3v3（或多队）战斗场”，复用原 3v3 模拟器的微观按 tick 执行逻辑。

3. **资源与装备系统（Loot）**
   - 队伍在宏观移动时，根据所在区域的物资丰富度提升一个名叫**装备值**的新属性。
   - 装备值直接折算为局内血量上限、护甲上限和伤害系数（模拟升紫甲、红甲和装备配件）。

4. **缩圈与安全区机制（The Ring）**
   - 整局游戏分为 **6 个缩圈阶段（Ring 1 ~ Ring 6）**，每个阶段由"等待期"和"缩圈期"两个子阶段交替构成：
     - **等待期**：安全区保持不动，队伍有充裕时间搜刮物资、转移进圈或主动交战。等待时长随阶段推进逐步缩短（初期约 60 tick，末期仅 10 tick），节奏逐步加快。
     - **缩圈期**：安全区从当前半径线性缩小至本阶段目标半径，圈内队伍被迫向更小的区域集中，圈外队伍则需尽快进圈。缩圈时长同样随阶段递减。
   - 各阶段圈半径逐步收紧，典型设定为 1500（初始，大于全图）→ 950 → 600 → 380 → 200 → 110 → 35，最终圈极小，几乎强制存活队伍进行贴身决战。初始圈半径 1500 大于地图对角线半长（~1414），确保开局时整个地图都在安全区内，随后从地图外开始收缩。
   - **圈外伤害随阶段递增**：初期圈外伤害较低（每 tick 扣 1 HP），后期决赛圈伤害大幅提高（最高每 tick 扣 8 HP），"抗毒苟活"策略在后期完全不可行。
   - **缩圈目标位置随机化**：每个新阶段的目标圈圆心并非固定在地图中央，而是从当前圈内部**随机选取一个位置**。约束条件为目标圈必须完全位于当前圈之内（即目标圆心与当前圆心的距离 ≤ 当前半径 − 目标半径），确保圈的收缩逻辑自洽。这意味着每局游戏的缩圈路径完全不同，队伍无法预判"永远往地图中心跑"，必须根据每阶段刷新的圈位动态调整行进路线，极大增加了战术多样性和不可预测性。
   - **等待期目标圈预览**：缩圈等待阶段，地图上会以蓝色虚线提前标示出下一个安全区的位置与范围，队伍在搜刮完成后可立即向目标区域转移，无需等到缩圈开始才被动反应。
   - 缩圈强制所有存活队伍向不断缩小的安全区聚集，极大增加中后期相遇与交火概率。

5. **多队混战（劝架机制）**
   - 当地图某区域发生战斗时，会产生“枪声警报”。
   - 周边原本处于游荡或搜集状态的队伍有一定概率被枪声吸引（取决于队伍的“激进度”配置），改变移动路线前往交火区域。
   - 一旦加入，原双队战斗场无缝升级为多队混战（如 3v3v3），目标选择逻辑增加“攻击血量最低队伍的成员”等权衡。

## 三、数据结构设计补充

### 3.1 队伍属性扩展 (Team)
- 基本属性保留：枪法、战斗经验、地形优势。
- 新增属性：
  - **当前坐标 (x, y)**：队伍在 2D 地图上的位置。
  - **当前状态**：[跳伞中, 搜集物资, 移动进圈, 战斗中, 已淘汰]
  - **装备值 (0~100)**：反映队伍当前总体的护甲等级和武器质量。
  - **激进度 (Aggressiveness)**：决定是否主动寻找敌人以及向枪声移动的意愿。
  - **队伍累计总伤害 (teamTotalDamage)**：队伍在一局游戏中造成的总伤害，持续累积至游戏结束。用于驱动**进化甲**等级提升（详见战斗模拟器设计 v2 §3.4）。
  - **当前进化甲等级**：[白/蓝/紫]，由 `teamTotalDamage` 决定：<350 为白色(50甲)，≥350 为蓝色(75甲)，≥1100 为紫色(100甲)。

### 3.2 战斗实例场 (Combat Instance)
- 参战队伍列表（可动态加入）。
- 局部微观 Tick 计数器。
- 地形优势：在防守区域被袭击的一方，或占领特定POI建筑的一方获得临时提升。

## 四、大逃杀模拟流程

### 阶段 1：初始化与跳伞
- 生成大地图网格及各个物资点（POI）的坐标区域和等级。
- 初始化 20 支队伍（60人），设定随机算法确定不同的落地 POI。
- 所有队伍的 `teamTotalDamage` 初始化为 0，进化甲等级初始为**白色（50甲）**。
- 设定初始安全区半径 1500（大于地图对角线半长约 1414，完全覆盖全图）。随机生成第一阶段缩圈的目标圆心和半径（目标圈必须完全位于初始圈内），为全局缩圈路径奠定随机基调。
- 启动 **宏观地图 Tick** = 0。

### 阶段 2：宏观主循环 (每 1 宏观 Tick 处理一次)
1. **环境更新**
   - 根据当前缩圈阶段和子阶段（等待/缩圈）推进圈的状态：
     - 若处于**等待期**且等待计时已满，则切换为**缩圈期**，重置计时器，并向全局广播缩圈开始事件，宣告本阶段目标圈的位置与半径。
     - 若处于**缩圈期**，每 tick 将当前圈的半径向目标半径递减，同时圆心向目标圆心平滑移动；当半径缩至目标值时，进入下一阶段——随机生成新的目标圆心和半径（约束为目标圈完全位于当前圈内），并重置为等待期。若已为第 6 阶段且缩圈完成，则圈不再变化，直至游戏结束。
   - 处于当前圈界线之外的队伍，每 tick 受到对应阶段的圈外伤害（直接扣除队员 HP），伤害随阶段递增。
2. **位置与状态更新**
   - 对于非战斗状态的队伍：
     - 若处于毒圈外，必定以最快速度朝安全区目标圆心方向移动。队伍始终优先向**本阶段目标圈的中心**靠拢（无论等待期还是缩圈期），提前规划进圈路线，而非被动等待缩圈发生后才行动。
     - 若处于圈内且该区域有物资，搜集物资（装备值缓慢随Tick上涨，获得临时血包配额）。
     - 物资搜刮完毕后进入随机巡逻或蹲守（依队伍战术配置而定）。
3. **相遇碰撞判定**
   - 计算所有处于非战斗状态队伍之间的距离。
   - 距离小于“交火判定半径”（如 100米）的队伍自动转入“战斗中”状态，并在该坐标实例化一个 **Combat Instance（战斗场）**。
4. **周边听觉响应（黄雀在后）**
   - 当某处存在 Combat Instance 时，判定距离该地中等范围（如 300米）内的队伍。
   - 根据“激进度”掷骰确认是否前去参战。若是，向此处移动并最终加入大混战。

### 阶段 3：微观战斗决算 (战斗实例内部执行)
- 进入战斗实例的队伍，其战斗控制权切入 **微观按 tick 模拟器**（复用3v3引擎逻辑，含进化甲系统）。
- 根据微观Tick进行开火判定、掩体换弹、击倒和救援。
- 战斗中所有队伍造成的伤害实时累加到各自的 `teamTotalDamage`，达到阈值（350/1100）时触发进化甲升级，全员护甲上限提升（白50→蓝75→紫100）。
- 战斗结束条件：该实例中仅剩下一支队伍存活（或各方脱离战斗）。
- 胜利队伍：
  - 触发"舔包"结算：该 Combat Instance 中所有**存活队伍**瓜分被淘汰队伍 `equipValue` 的 70%（逐点随机分配，单队上限 100），随后消耗局内血包配额回复当前 HP 与护甲。
  - **战后全员恢复机制**：微观战斗结束后，所有存活队伍（包括最终胜利方和可能中途退出的劝架队伍）的队员自动恢复至满状态——生命值回满、护盾回满至当前进化甲等级的 `shieldMax`（白50/蓝75/紫100）、弹药重置，所有倒地或死亡的队员复活并清除战斗中的临时状态（如倒地倒计时、救援状态等），确保宏观主循环中所有队伍以满编满状态继续行进。
  - 状态解除锁定为"非战斗状态"，回到宏观主循环继续行进。
  - **注意**：`teamTotalDamage` 不随战后恢复清零，跨战斗持续累积，确保进化甲进度在整个大逃杀对局中持续生效。

### 阶段 4：结算条件
- 每次有队伍全员阵亡时，发出全局淘汰广播（例如：“小队第 13 队已被淘汰，剩余 8 队”）。
- 当当前存活队伍总数 = 1 时，跳出整局主循环，游戏结束。
- 生成最终《冠军战报》，展示排名、队伍总击杀、总伤害及存活时间序列。

## 五、可视化及日志要求

1. **大地图态势图（Mini-Map Tracker）**
   - 按时间输出包含所有存活队伍位置的 2D 快照数据，辅以缩圈路径和交火热点标志。
2. **全局击杀公告（Kill Feed）**
   - `[宏观Tick 240] Team14 (激进派) 发起劝架，加入 碎片东部 混战。`
   - `[宏观Tick 245] Team14-恶灵 使用 獒犬霰弹枪 击倒 Team5-直布罗陀`
   - `[微观Tick 84] Team3 累计伤害达到 350，进化甲升级为 蓝色 (75甲)！`
   - `[宏观Tick 600] 缩圈完成，Team20 因处于圈外流血阵亡，剩余 3 队存活。`
   - `[微观Tick 312] Team7 累计伤害达到 1100，进化甲升级为 紫色 (100甲)！`

## 六、进阶：RNG与随机性挑战
大逃杀模式具有极强的不可预测性（RNG）：
- **落地Roll点（落地架）**：多队落于同一热门物资区时，最初战斗由于无护甲、无武器导致极高随机性，强队也有可能早早出局。
- **残局资源消耗**：经历多次战斗的队伍可能缺少恢复物资，导致高击杀却输给了满补给的“避战苟分队”。
设计时，调整“物资刷新系数”和“战斗内护甲破损率”可以极大影响对局的最终生态偏好（鼓励打架 还是 鼓励防守选点）。
