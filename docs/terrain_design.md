# 地形与掩体联动设计（Map Layer + Micro Terrain）

## 一、设计目标

1. 引入基于坐标的地图层，为宏观移动和战斗触发提供环境上下文。
2. 每场战斗为每个队伍独立分配微观地形，解决“同坐标同地形”的同质化问题。
3. 微观地形直接渗透掩体机制，使城区、丘陵、开阔地产生截然不同的战斗体验。
4. 与现有状态机完全解耦：队员的 `idle/shooting/healing/...` 状态由原有 Burst-Fire 状态机驱动，微观地形仅提供环境参数。

## 二、双层架构

```
地图层 (Map Layer / Macro)
├─ 由坐标决定的静态 Zone
├─ 类型: Urban / Hills / Open
└─ 作用: 决定该区域内战斗的“微观地形候选池”

微观地形层 (Micro Terrain)
├─ 每个队伍进入战斗时独立掷点分配
├─ 一旦确定，整场战斗不变
└─ 作用: 直接提供掩体系数表 + 地形修正值
```

**核心差异**：同一场战斗中，Team A 可能在城区“室内”（掩体极好），Team B 可能在同区域“巷口”（掩体一般）——**同坐标，不同微观地形**。

## 三、地图层（Map Layer）

在初始化时生成若干圆形区域：

| 宏观地形 | 数量 | 半径 | 颜色标识 | 核心特征 |
|---------|------|------|---------|---------|
| **Urban（城区）** | 3 | 200~300 | 灰色 | 建筑密集，掩体丰富，物资多 |
| **Hills（丘陵）** | 3 | 250~350 | 棕色 | 有高低差，地势不均 |
| **Open（开阔地）** | 4 | 300~400 | 浅黄 | 极少掩体，地势平坦 |

**查询方式**：`getMacroTerrainAt(x, y)` → 遍历 Zone，取优先级最高者（`Urban > Hills > Open`）。Zone 可以重叠，重叠时按优先级取。

**物资联动**：Urban 区域内 `equipValue` 增长速度 +50%。

## 四、微观地形层（Micro Terrain）

当战斗实例化时（两队距离 < 交火阈值），根据战斗中心坐标的**宏观地形**，为每个参战队伍**独立随机分配**一个微观地形。

### 4.1 微观地形数据结构

每个微观地形包含：
- `name`：显示名称（如“建筑内”、“坡顶”）
- `coverTable`：覆盖现有状态掩体值的完整映射表
- `terrainBonus`：参与地形差计算的修正值

### 4.2 Urban（城区）微观地形池

| 微观地形 | 概率 | `terrainBonus` | `coverTable`（idle / shooting / healing / reviving / in_cover） |
|---------|------|---------------|--------------------------------------------------------------|
| `indoor`（建筑内） | 30% | +15 | 0.6 / **0.4** / 0.2 / 0.2 / 0.2 |
| `street`（街道） | 40% | +5 | 1.0 / 0.6 / 0.35 / 0.35 / 0.35 |
| `rooftop`（楼顶） | 20% | +20 | 0.6 / 0.6 / 0.35 / 0.35 / 0.35 |
| `alley`（窄巷） | 10% | +10 | 0.6 / 0.6 / 0.25 / 0.25 / 0.25 |

### 4.3 Hills（丘陵）微观地形池

| 微观地形 | 概率 | `terrainBonus` | `coverTable`（idle / shooting / healing / reviving / in_cover） |
|---------|------|---------------|--------------------------------------------------------------|
| `top`（坡顶） | 25% | +20 | 0.6 / 0.6 / 0.35 / 0.35 / 0.35 |
| `mid`（坡腰） | 30% | +5 | 1.0 / 0.6 / 0.35 / 0.35 / 0.35 |
| `bottom`（坡底） | 20% | -10 | 1.0 / **0.8** / 0.6 / 0.6 / 0.6 |
| `side`（侧翼） | 25% | 0 | 1.0 / 0.6 / 0.35 / 0.35 / 0.35 |

### 4.4 Open（开阔地）微观地形池

| 微观地形 | 概率 | `terrainBonus` | `coverTable`（idle / shooting / healing / reviving / in_cover） |
|---------|------|---------------|--------------------------------------------------------------|
| `rock`（岩石后） | 25% | +5 | 0.6 / 0.6 / 0.35 / 0.35 / 0.35 |
| `dip`（洼地） | 25% | 0 | 0.6 / 0.6 / 0.35 / 0.35 / 0.35 |
| `exposed`（完全暴露） | 30% | -15 | **所有状态: 1.0** |
| `grass`（长草地） | 20% | -5 | 0.8 / 0.8 / 0.6 / 0.6 / 0.6 |

## 五、双层联动机制

### 5.1 地形差公式

```
有效地形值 = 队伍基础 terrain 属性 + 队伍微观地形.terrainBonus
terrainDiff = 攻方有效地形值 - 守方有效地形值
```

与现有 `combat_v2` 设计完全兼容：差值 >20 攻方命中率 +15%，<-20 攻方命中率 -15%，阈值不变。

### 5.2 掩体公式

```javascript
// 优先读取微观地形 coverTable[state]
// 若无对应条目，fallback 到原有固定值
cover = defender.microTerrain.coverTable[defender.state] ?? defaultCover(state)
```

例如 `indoor` 的 `shooting` 是 0.4，直接替代了原来的 0.6；`exposed` 强制所有状态为 1.0。

### 5.3 劝架队伍的微观地形

第三方加入时**重新独立掷点**，不受已在场队伍影响。可能出现原两队都在 `street`，劝架队掷到 `rooftop` 获得制高点优势。

## 六、核心差异示例

**示例 1：城区遭遇**
- Team A 掷到 `indoor`：shooting 掩体 0.4，terrainBonus +15
- Team B 掷到 `street`：shooting 掩体 0.6，terrainBonus +5
- 地形差 = (50+15) - (50+5) = +10 → 攻方命中率正常
- 但 Team A 队员射击时被打中的概率比 Team B 低 33%

**示例 2：丘陵遭遇**
- Team A 掷到 `top`：terrainBonus +20
- Team B 掷到 `bottom`：terrainBonus -10，掩体全面降级
- 地形差 = +30 → 攻方命中率 -15%，且坡底队员所有状态掩体更差

**示例 3：开阔地被劝架**
- 原两队均掷到 `rock`，互相僵持
- 劝架队掷到 `exposed`，无任何掩体
- 劝架队虽然地形差吃亏，但可能趁乱收掉残血

## 七、与现有系统的融合

| 模块 | 联动方式 |
|------|---------|
| **相遇检测** | 距离 < 阈值时，查询坐标宏观地形，触发微观地形分配 |
| **装备系统** | Urban 区 `equipValue` 增长速度 +50% |
| **缩圈** | 毒圈伤害不受地形影响，但跑毒中被拦截时，被迫在不利微观地形接战 |
| **战后恢复** | 微观地形战斗结束后清除，下次战斗重新掷点 |
| **状态机** | **完全不干涉**。队员状态由原有 Burst-Fire 逻辑驱动，微观地形只提供环境参数 |
